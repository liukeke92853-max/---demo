历史PRD · V1.3

本文件保留历史轨迹，当前需求以主入口最新PRD为准。

本次新增 / 改造

渠道新增一级、二级推广位，均改为先发送合作邀请。目标机构人员在小程序接受后，推广位才生效；未接受时不赋予推广位身份，不产生有效邀约权限或分成。

一级邀请以渠道名称展示邀请方；二级仍由渠道发起配置，小程序展示所选直接上级为邀请方。

新增关闭能力。关闭一级时，名下合作中的二级一起关闭，全部邀约归顶层渠道；单独关闭二级时，其邀约也直接归顶层渠道。关闭记录不可再次启用，重新合作须重新邀请并接受。历史订单及待结算收益保留原归属，关闭后新订单归顶层渠道。原记录及操作日志留存。

二级推广位表单将关联上级及其分成比例集中到“上级信息”区块，方便对应修改；当前推广位自身的分成比例独立展示。分成说明明确以对应订单的渠道提成金额为基数。

字段与规则

新增 / 改造项控件及默认值规则
合作状态筛选顶部下拉单选；默认全部全部、待接受、合作中、已关闭。与既有筛选条件取交集。
合作状态列只读状态标签邀请成功后为待接受；接受后为合作中；关闭后为已关闭。
列表操作文字按钮合作中：编辑、关闭、日志；待接受：日志；已关闭：日志、重新邀请。已关闭不提供启用操作。
合作邀请小程序消息及接受邀请按钮文案“{邀请方名称}邀请您成为他的合作伙伴”。一级取渠道名称，二级取直接上级名称；不把实际后台操作人与业务邀请方混淆。
日志按机构查看，只读操作时间、操作人、操作、操作内容；记录邀请、接受、关闭及邀约归属变化。重新合作后仍可查看历史。

操作交互与弹窗

新增 / 重新邀请弹窗

结构 / 字段控件、默认值及编辑范围联动与校验
标题新增推广位 / 重新邀请按入口展示，无额外编号或说明。
推广位机构 ID必填数字输入；新增为空，重新邀请带出机构ID；可编辑校验机构存在、不能邀请渠道自身、不得创建冲突的有效合作或重复待接受邀请。跨渠道排他范围待确认。
推广位类型必填单选；一级 / 二级；新增默认一级，重新邀请带出原类型；可编辑选二级展示“上级信息”区块，其中关联上级与上级分成比例并排展示；窄屏同一区块内上下排列。切回一级清空并隐藏整个区块。
关联上级二级时必填下拉单选；新增为空，重邀原上级仍有效时带出；可编辑位于“上级信息”区块；仅本渠道合作中的一级推广位，不可选择自身或已关闭上级。选择或更换上级后立即带出对应上级当前比例，不保留上一上级的输入值。
分成比例必填数值；重新邀请带出原值，可编辑；新增默认按线上配置，具体值待确认沿现有比例校验，显示百分比，当前后端以基点存储。Demo未代入生产默认值，新增时留空。
上级分成比例与上级名称同区展示；二级时必填数值，未选择上级时为空且禁用；选中后带出当前比例并可编辑修改对应上级的有效分成比例；发邀请时只保存提议值，接受生效后同步更新，未接受不提前修改。接受时重新校验。当前推广位及上级比例之和不得超过100%。
分成说明只读文字，位于分成配置下方一级文案：“例如推广位分60%：每100元渠道提成，推广位拿60元，渠道留40元。”二级文案：“例如推广位分60%、上级分20%：每100元渠道提成，推广位拿60元，上级拿20元，渠道留20元。两个比例相加不能超过100%。”上级区块补充“合作生效后同步更新该上级的分成比例”。
取消 / 发出邀请底部按钮取消不保存；校验错误在表单内反馈并保留输入。发出成功关闭弹窗、列表新增待接受记录；通知成功不等于合作生效。

编辑推广位弹窗

标题为“编辑推广位”。字段、上级信息区块、分成说明、控件及联动与上表共用；机构ID回显且不可编辑，推广位类型及当前分成比例回显当前配置并可编辑，二级关联上级与上级比例回显当前有效值且可编辑。上级区块提示“保存后同步更新该上级的分成比例”。

取消不保存；保存前校验当前机构归属、上级有效性、层级及分成比例。不能将仍有下属的推广位改成二级。校验失败在表单内提示并保留输入；保存成功后关闭弹窗、刷新列表、同步所选上级有效比例并保存变更日志。不另行发送邀请或改变当前合作状态。

小程序接受邀请

消息只展示合作邀请及接受邀请操作。用户点击接受后，后端校验当前登录机构、邀请状态、渠道及上级有效性、合作配置及关系冲突。成功后转合作中并记录处理人、时间；重复处理不得产生重复合作。机构内接受权限及消息具体承接入口待确认。

关闭推广位弹窗

结构 / 字段规则
标题确认关闭{机构名称}？
关闭对象只读展示机构ID及推广位等级；关闭一级时列出同时关闭的合作中二级机构名称及机构ID。无额外输入字段。
继承范围展示受影响邀约数量、机构名称及顶层渠道名称，不展示自定义邀约编号。
影响说明关闭后不可再次启用，重新合作须重新邀请；历史订单及待结算收益保留原归属，关闭后新订单归顶层渠道。
取消 / 确认关闭取消不改变状态；确认前再次检查关闭对象与下属合作状态，关闭和邀约继承一起成功并保存日志。失败不得出现部分关闭、部分继承。
成功反馈关闭成功；列表同步更新为已关闭，日志记录关闭对象和邀约前后归属。

操作日志弹窗

点击列表“日志”打开对应机构的操作日志，默认按操作时间倒序。展示操作时间（精确到秒）、操作人、操作、操作内容；邀约继承按机构名称展示原归属及目标渠道。日志只读，无记录时显示“暂无操作日志”。点击关闭按钮或Esc关闭弹窗。

前后状态流转

一级：渠道发出邀请 → 待接受 → 目标机构接受 → 合作中。

二级：渠道选择关联上级并发出邀请 → 以上级名义展示邀请 → 待接受 → 目标机构接受 → 合作中。

关闭：合作中 → 确认关闭 → 已关闭；若为一级，同时关闭合作中的二级，邀约归顶层渠道并留日志。

重新合作：已关闭记录保留 → 发出新的邀请 → 待接受 → 再次接受后生效。不得覆盖原关闭及继承记录。

待确认项

  1. 一级名下尚待接受的二级邀请在一级关闭后如何处理；是否撤回、过期或增加拒绝邀请能力。未确认前不增加对应按钮、状态或关闭阻断规则。
  2. 继承覆盖的邀约状态、保护期限及与渠道现有关系重复时的去重方式；当前演示数据仅覆盖生效中的邀约。
  3. “关闭后新订单”的具体判定时间字段，以及迟到订单、退款和重算如何匹配关闭时点。历史保留、新订单归渠道的业务原则已确认。
  4. 机构中谁可接受邀请，通知接收账号、消息入口及实际发送方式；发送失败重试规则。
  5. 跨渠道机构排他范围、待接受期间配置变化的处理方式，以及重新合作后是否迁回原邀约。
  6. 新增表单的线上默认值。不将演示初始值视为生产默认值。

研发影响与验收

依据此前已读取的本地代码：现有推广位创建直接写合作中；停用方法会将邀约改为失效。本次须将创建改为邀请确认，将推广位关闭改为经确认的继承流程。现有二级新增可能提前修改上级分成，引入邀请后须避免未接受即影响有效配置。

现有推广位表的渠道ID与机构ID联合唯一约束会影响同一机构重新合作；研发需调整存储方式，保留历史关系与日志。数据结构由研发设计。订单来源还会读取授权申请中的推广位关联，不能仅修改邀约表；须同时保证后续新订单归渠道、历史订单及收益不被覆盖。

发送、接受与关闭均须做身份、归属、状态与并发校验。关闭及继承需保证事务一致性，重复提交不产生重复记录。小程序邀请消息的实际接口需研发补齐。

场景验收结果
发送一级邀请列表待接受，消息显示渠道名称；接受前不生效，接受后转合作中。
发送二级邀请由渠道操作，消息显示直接上级；接受前不改有效分成。
上级信息联动选中上级后名称和比例同区对应；更换时带出新上级当前值，切回一级隐藏清空。编辑保存后同步上级比例；新邀请接受前不改上级，接受后才同步。
重复或越权接受不生成重复合作，不允许非目标机构处理。
关闭二级邀约归顶层渠道，关闭状态、原记录及归属日志留存。
关闭一级合作中的二级一起关闭，一级和二级邀约全部归顶层渠道。
重新邀请仍需再次接受；旧关闭记录和历史日志保留，不提供再次启用。
订单与收益历史订单及待结算收益不变，关闭后新订单归顶层渠道。
界面和日志没有自加业务编号、未确认的功能入口及无关说明。
